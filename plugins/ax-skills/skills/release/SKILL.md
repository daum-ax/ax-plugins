# 버전 남기기 (release)

지금 상태에 `v1`, `v2` 같은 버전 이름을 붙여 팀 저장소에 남긴다. 나중에 "이 시점으로
돌아가기"나 "이 버전을 배포하기"의 기준점이 된다.

버전은 git의 태그(tag — 특정 커밋에 붙이는 이름표. 커밋은 계속 쌓이지만 태그는 그 자리에
고정된다)로 남긴다. 번호는 이 스킬이 정하고(기술 결정, `git-collab.md` §6), 설명 한 줄은
사용자가 정한다(내용 결정, §7).

먼저 `${CLAUDE_PLUGIN_ROOT}/references/git-collab.md`를 읽는다 — 어휘(§1), 마무리
카드(§2), 에러 번역표(§3), 원격 명령(§3.6), 안전 기준선(§5).

사용자가 **목록만** 원하면("버전 목록 보여줘" / "예전 버전 뭐 있어?") 아래 **목록 모드**로
간다.

## Process

### Step 1: 조용히 확인

```bash
git rev-parse --git-dir 2>&1
git status --porcelain 2>&1
git rev-parse HEAD 2>&1
git remote get-url origin 2>&1
```

- git 저장소가 아니면 `/ax-skills:status`로 넘긴다.
- 커밋 안 된 변경이 있으면 "커밋 안 된 변경이 {n}개 있어요. 버전은 커밋된 상태에만
  붙어요." 하고 `/ax-skills:commit`을 먼저 권한다. **자동으로 커밋하지 않는다.**
- 팀 저장소 주소(origin)가 없으면 아래 명령을 돌리지 않고 `/ax-skills:push`를 먼저
  권한다. 버전은 **팀 저장소에 올라간 커밋에만** 붙인다.

origin이 있으면 팀 저장소를 건드리는 명령은 §3.6대로 **미리 알리고 시간 제한을 걸어** 실행한다("팀
저장소 연결을 확인할게요 — 몇 초 걸릴 수 있어요"):

```bash
git -c http.lowSpeedLimit=1000 -c http.lowSpeedTime=15 fetch --tags 2>&1
git branch -r --contains HEAD 2>&1
```

- 지금 커밋이 팀 저장소에 없으면(`branch -r --contains` 출력이 빔) `/ax-skills:push`를
  먼저 권한다.
- `fetch` 실패는 §3 번역표로 분류한다 — 맨 윗줄부터. 네트워크면 VPN 안내 후 **정지**,
  인증이면 `/ax-skills:github-login`.

### Step 2: 이미 버전이 붙어 있으면 멈춘다

```bash
git tag --points-at HEAD --list 'v*'
```

결과가 있으면 "지금 상태는 이미 `{태그}`로 남겨져 있어요." 라고 알리고, 그 태그 이름과
커밋 SHA를 결과로 돌려준 뒤 끝낸다. **같은 커밋에 버전을 두 개 붙이지 않는다.**

### Step 3: 다음 번호 정하기

```bash
git tag --list 'v*' --sort=-v:refname
```

`^v[0-9]+$` 에 맞는 것 중 가장 큰 번호 + 1. 하나도 없으면 `v1`.

- semver(`v1.2.3`)는 쓰지 않는다 — 비개발자에게 "마이너/패치" 구분을 묻게 된다.
- 형식이 다른 기존 태그(`v1.2.3`, `release-3` 등)는 번호 계산에서 무시하고 **건드리지
  않는다.**
- 번호는 사용자에게 묻지 않는다.

### Step 4: 설명 한 줄

직전 버전 이후의 커밋을 본다:

```bash
git log {직전 태그}..HEAD --oneline     # 첫 버전이면: git log --oneline
```

그 내용으로 한 줄 설명을 제안하고 AskUserQuestion:

> "이번 버전을 `v4`로 남길게요. 설명은 이렇게 적을까요? — '회의실 예약 목록에 날짜 필터 추가'
> ① 이대로 ② 설명 고칠래요 ③ 그만두기"

설명은 한국어여도 된다 — 태그 이름이 아니라 메시지라 주소에 들어가지 않는다.
질문 문구는 제출 전에 한 번 다시 읽는다(§7).

### Step 5: 만들고 올리기

```bash
git tag -a v4 -m "회의실 예약 목록에 날짜 필터 추가" HEAD
git -c http.lowSpeedLimit=1000 -c http.lowSpeedTime=15 push origin refs/tags/v4 2>&1
```

- annotated tag(`-a` — 설명·만든 사람·날짜가 함께 기록되는 태그)만 쓴다. 이 기록이 배포
  이력 화면에 그대로 쓰인다.
- **이 태그 하나만** push한다. `--tags`는 쓰지 않는다 — 내 컴퓨터에만 있는 다른 태그가
  딸려 올라간다.
- push가 `already exists`로 거부되면 다른 곳에서 같은 번호를 먼저 썼다는 뜻이다. **내
  컴퓨터의** 태그만 지우고(`git tag -d v4` — 아직 올라가지 않은 것이라 안전하다) Step 1부터
  다시 번호를 매긴다. 사용자에게 한 줄로 알린다: "다른 곳에서 `v4`를 먼저 써서 번호를 다시
  매길게요."
- 그 밖의 실패는 §3 번역표 (맨 윗줄부터). 실패로 끝날 때 방금 만든 태그가 내 컴퓨터에만
  남아 있으면 그 사실을 알린다 — 다음 실행의 Step 2가 그 태그를 보고 멈추지 않도록, 이
  경우에도 `git tag -d {태그}`로 지운다(올라가지 않은 태그라 안전하다).

### Step 6: 마무리

`git-collab.md` §2 카드. 예:

```
### 지금 상태
- `v4` — 회의실 예약 목록에 날짜 필터 추가 — 가 팀 저장소에 올라갔어요.

### 다음에 할 수 있는 것
- 이 버전을 배포하려면: "배포해줘"
- 지금까지 버전 보기: "버전 목록 보여줘"
```

카드 아래에 **태그 이름과 커밋 SHA**를 분명히 적는다 — 배포 흐름이 이어서 쓸 값이다:

```
버전: v4
커밋: {git rev-parse HEAD 전체 값}
```

## 목록 모드

읽기만 한다. 네트워크를 건드리지 않으므로 내 컴퓨터가 아는 버전만 나온다 — 그 사실을 한
줄로 말한다.

```bash
git tag --list 'v*' --sort=-v:refname --format='%(refname:short)|%(creatordate:short)|%(contents:subject)'
```

"버전 · 날짜 · 설명" 표로 보여준다. raw 출력을 그대로 보여주지 않는다. 버전이 하나도
없으면 "아직 남긴 버전이 없어요. '버전 남겨줘'라고 하시면 `v1`부터 만들어요."

## 절대 하지 않는 것

- 팀 저장소에 있는 태그 옮기기·지우기.
- `push --force`로 태그 덮어쓰기.
- lightweight 태그(`-a` 없는 태그).
- push 안 된 커밋에 태그 붙이기.
- 버전 번호를 사용자에게 묻기.
- 사용자 확인 없이 커밋하기 (`git-collab.md` §5).
- raw git 출력 그대로 보여주기.
