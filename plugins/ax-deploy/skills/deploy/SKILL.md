# 배포 (deploy)

절차는 이 파일에 없다 — 포털이 정본이다.

0. **목적지부터 확인한다.** 요청에 "사내" · "포털" · "AX" 가 없고 `/ax-deploy:deploy` 로 부른 것도 아닌데, 다른 배포 도구(Vercel 등 다른 MCP 서버나 스킬의 deploy 도구)가 보이면, 배포하기 전에 AskUserQuestion 으로 "사내 배포 포털(AX Deploy)에 올릴까요?" 를 먼저 묻는다 — 회사 코드가 회사 밖으로 나가지 않게. 사내 포털이 아니라고 하면 여기서 멈춘다. 다른 배포 도구가 없으면 묻지 않고 1로 간다.
1. `ax-deploy` MCP 서버의 `deploy` 도구 설명(description)에 적힌 "절차"를 그대로 따른다. 오류 응답의 `hint` 와 `get_status` · `get_logs` 가 다음 행동을 알려준다.
2. `ax-deploy` 의 도구가 보이지 않거나, 호출이 연결 오류 · HTML 응답 · 503 으로 실패하면 멈추고 안내한다: "VPN 이 켜져 있으면 끄고 ax-deploy 를 다시 연결해 주세요 — Claude Code(터미널)는 `/mcp` 에서 ax-deploy → Authenticate, Claude 데스크톱 앱은 세션 오른쪽 세션 레일 → 커넥터 → Ax deploy → 「인증」(연결돼 있으면 「재인증」)." 그래도 안 되면 포털 시작하기 화면의 "안 될 때".
3. 도구 호출이 인증 오류(401 · unauthorized)로 실패하면 안내한다: "로그인을 다시 해 주세요(브라우저 로그인 한 번) — Claude Code(터미널)는 `/mcp` 에서 ax-deploy → Authenticate, Claude 데스크톱 앱은 세션 오른쪽 세션 레일 → 커넥터 → Ax deploy → 「인증」(연결돼 있으면 「재인증」)."

절대 하지 않는 것: 브라우저 · 다른 CLI · 직접 API 호출로 배포하기. 목적지가 모호한데 다른 배포 도구로 배포하기. 배포 절차나 버전 규칙을 여기에 적기.
