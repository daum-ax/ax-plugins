# 0004 — 배포 연결 플러그인 ax-deploy, 정적 토큰으로 먼저 (2026-10-06)

**문제.** git 도우미(`ax-skills`)는 플러그인 한 번 설치로 얻지만, 사내 배포 포털 연결은
포털에서 토큰이 박힌 `claude mcp add` 명령을 받아 터미널에 붙여 넣어야 했다. 그래서
"커밋 → 버전 남기기 → 배포"가 한 묶음 도구로 이어지지 않았다.

**결정.** 같은 marketplace 에 두 번째 플러그인 `ax-deploy` 를 둔다. 설치 창(`userConfig`)에서
포털 주소(기본값 있음)와 배포 토큰을 받고, 토큰은 원격 MCP 의 `Authorization` 헤더에 넣는다.
포털의 OAuth 가 생기면 `userConfig.token` 과 `headers` 만 지운다.

- **플러그인에는 포털 규칙이 없다.** 배포 절차·버전 태그·재시도·오류 안내의 정본은 포털 MCP 의
  `deploy` 도구 설명과 오류 hint 다. 이 플러그인은 릴리즈가 드물어서 절차를 복사해 두면
  포털과 반드시 어긋난다. 스킬은 "도구 설명의 절차를 따른다"는 트리거 표면만 갖는다.
- **회사 도메인 원칙의 예외 — `plugins/ax-deploy/` 한정.** 포털 주소를 기본값으로 적는다.
  기본값이 없으면 비개발자가 주소를 직접 쳐야 하고, 그 주소는 어차피 사용자가 알아야 하는
  값이다. 유출 검사 정규식은 바꾸지 않았고, 이 경로 밖으로는 번지지 않는다.
- **토큰 보관 = 키체인.** `sensitive: true` 값이 헤더에 치환되는지 설치로 확인했다
  (2026-10-06, Claude Code 2.1.290 — 연결 성공, 설정 파일에는 주소만 남음).
- **같은 이름의 수동 연결이 플러그인 연결을 가린다**(같은 날 확인). 그래서 설치 안내에
  "먼저 `claude mcp remove ax-deploy -s user`"를 둔다.
- **`ax-skills` 에 의존한다.** 포털이 "버전 태그가 없다"고 답하면 `/ax-skills:release` 가
  태그를 만든다.

배경 문서: 배포 포털 저장소의 책임 분할 문서 §5 결정 1.
